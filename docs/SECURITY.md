# 安全约束与上线检查

## 沙盒与管理后台

- 访客数据来自虚构商品、模拟订单和固定规则。页面内操作只更新当前浏览器沙盒，无需匿名写接口。
- 管理后台预设关闭。初始化使用后端 `python -m app.password` 生成带随机盐的 scrypt 密码散列，密码至少 14 字符。密钥、密码散列和 Cookie 都应留在授权环境中。
- 登录签发高熵随机令牌，仅保存 SHA-256 摘要，8 小时过期。同一实例保留最近 12 个会话，退出立即吊销，修改密码散列使旧会话失效。Cookie 默认 `Secure`、`HttpOnly`、`SameSite=Strict`。`VOYAGEDECK_INSECURE_COOKIE=1` 仅用于本机 HTTP 调试。
- 管理写操作要求同源请求标记，前端使用同源 Cookie，应用未开放跨源 CORS。管理 API 设置 `Cache-Control: no-store`，事件流会反复确认会话有效性。生产应通过 HTTPS 网关，并按需对管理员入口增加来源限制。
- 单实例限制每 5 分钟 8 次登录尝试，每分钟 8 次推理，推理与密码校验分别串行。API 写入体上限 16 KiB，持久化记录上限 1000 条，SSE 同时最多 4 条。

## 模型出站权限和数据保留

- 模型模式支持固定 Mock 和 OpenAI-compatible HTTP。真实端点必须是部署者明确批准的公网 HTTPS 基址，管理页面不能替换为其他外部主机。禁止 URL 用户信息、非标准端口、查询及片段。部署者应确认批准域名和 DNS 由可信主体控制。
- `VOYAGEDECK_PROVIDER_API_KEY` 只在服务端环境设置，管理页只显示已配置状态。上游请求使用 TLS、固定 `/chat/completions` 后缀、请求超时与令牌上限、禁用重定向和隐式代理环境读取。上游响应大小限制为 256 KiB，严格校验草稿字段、长度与结束条件。
- 模型可产出文本供审阅。无执行工具、账户连接、外部支付、投放、客服发送和真实履约权限。管理推理内容会提交给批准的模型端点，调用可能由 Provider 计费，仅使用获准的演示或脱敏上下文。
- 已配置凭据出现在持久化输入时会拒绝，上游错误只返回整理后的原因，响应回显模型密钥时会丢弃草稿。管理员输入、产物及备注会按业务记录明文写入 SQLite，通用个人信息和第三方凭据检测不在当前版本范围。不要输入客户数据或任何密钥。
- `.env`、数据库及 WAL、密钥、参考图和日志均排除在 Git 之外。`.env.example` 仅含默认空值和配置名。数据卷和备份应由部署者限制权限，访问日志和截图避免留存凭据或个人资料。

## 交付验收与运营

- 开发分支执行了 npm 完整审计与运行依赖审计。运行依赖无已知发现，完整结果保留同一 Picomatch 公告在构建和 lint 链上的记录。GitHub 已撤回该公告，NVD 仍保留 CVE，应用的服务镜像使用 Python 且仅复制前端编译产物。 [GitHub 公告](https://github.com/advisories/GHSA-fc5q-39xc-vjpf) · [NVD 记录](https://nvd.nist.gov/vuln/detail/cve-2026-112366)
- pip-audit 扫描了 17 项 Python 运行依赖和 7 项开发依赖，未发现已知漏洞。Gitleaks 扫描本地开发 Git 历史和工作树，未发现密钥。扫描结果反映验收时的依赖版本与公告库状态。
- 上线前核对独立 Compose 项目、镜像版本、实际监听地址、网关最小变更、HTTPS、匿名管理接口和数据卷保护。公网演示应停用管理员口令和 API 文档，使用 Mock，管理操作可由有权限的本地实例验证。
- 真实模型合同测试使用仿真传输。真实模型的计费、模型标识、响应格式与组织数据政策仍需在有效凭据下另行确认。生产预检、启动、健康检查和回滚步骤见 [部署配置](../deploy/)。
